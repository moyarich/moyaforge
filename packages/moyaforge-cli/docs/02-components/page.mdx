# Install editable components

Configure the registry without generating a new site:

```sh
npx @moyarich/moyaforge-cli@latest init
npx @moyarich/moyaforge-cli@latest list
npx @moyarich/moyaforge-cli@latest add code-block code-group
npx @moyarich/moyaforge-cli@latest add search
```

The `add` command plans installation from the root `registry.json`, resolves component dependencies, and copies the canonical source into the configured UI directory. Installed components import their own CSS.

```tsx
import { CodeGroup, CodeTab } from "./components/ui/CodeGroup/CodeGroup.js";
```

`search` installs the reusable UI input from `packages/moyaforge-ui/src/components/Search/`. It does not install or configure the SQLite index by itself; `create --search` also enables the search adapter and generates the app-specific result wiring.

## Preserve local changes

```sh
npx @moyarich/moyaforge-cli@latest add code-group --dry-run --diff
npx @moyarich/moyaforge-cli@latest add code-group --overwrite
```

Local edits are preserved by default. `--overwrite` explicitly permits replacement, while `--no-install` copies files without running npm.

`--directory` changes the component installation root. `--registry` accepts a local repository directory, a `registry.json` file, or its URL. The optional `moyaforge.components.json` persists registry and directory selection between commands. It is separate from `registry.config.ts`, which configures authored MDX content discovery.

The same component source can be installed using the shadcn-compatible registry:

```sh
npx shadcn@latest add moyarich/moyaforge/code-block
```
