# Create a documentation project

Run the CLI in the directory where you want the generated application:

```sh
npx @moyarich/moyaforge-cli@latest create
npm run dev
```

By default, `create` generates a React/Vite/MDX site and starter documentation pages under `docs/`. It installs the registered `docs-shell` and `code-group` components into `src/components/ui/` with their required source files.

## Starter options

```sh
# Include a separate interactive playground route
npx @moyarich/moyaforge-cli@latest create --template hybrid

# Add the optional SQLite search adapter and reusable Search component
npx @moyarich/moyaforge-cli@latest create --search

# Add the published framework dependency
npx @moyarich/moyaforge-cli@latest create --mode package

# Generate an isolated documentation entry in an existing React project
npx @moyarich/moyaforge-cli@latest create --template existing
npm run docs:dev
```

The `existing` starter writes its Vite entry under `moyaforge/` and uses `docs:*` scripts so that existing host scripts and dependency versions are preserved.

Use `--directory <path>` to select a component source destination, `--registry <source>` for a registry directory or `registry.json` URL, and `--cwd <path>` to choose a project directory.

Use `--dry-run` to preview changes, `--diff` for proposed file differences, `--no-install` to skip npm installation, and `--overwrite` to permit replacing modified files.

## Template organization

The CLI recursively reads starter files from `templates/base/`. With `--search`, files in `templates/search/` overlay matching base paths. Documentation pages come from `templates/docs/`. The default package manifest is `templates/base/package.json`, with additional dependencies selected by the CLI.

The packaged file `templates/base/tsconfig.json.template` is written as `tsconfig.json` in consumer projects. Files belonging to the CLI are read directly; consumer files are inspected before changes are applied.
