# PreviewCodeEditor

Use `PreviewCodeEditor` to show a live React preview beside editable Monaco source files. It owns the file state and reset action; your `renderPreview` callback decides how edited files become a preview.

## Installation

<CodeGroup label="Install PreviewCodeEditor">
<CodeTab label="MoyaForge CLI">

```sh
npx @moyarich/moyaforge-cli@latest add preview-code-editor
```

</CodeTab>
<CodeTab label="shadcn">

```sh
npx shadcn@latest add moyarich/moyaforge/preview-code-editor
```

</CodeTab>
</CodeGroup>

The registry item installs the Preview source files and depends on
`@moyarich/moyaforge-monaco` for the editor. Install
`@monaco-editor/react` and `monaco-editor` and configure workers for
your bundler before rendering the editor. Other MoyaForge UI components
do not require Monaco.

## Usage

Pass the editable files and a renderer that consumes their current values:

```tsx
<PreviewCodeEditor
  title="Counter"
  files={[{ name: "Counter.tsx", language: "typescript", value: source }]}
  renderPreview={(files) => <Counter source={files[0]?.value ?? ""} />}
/>
```

Provide `usageSource` when the Code view should include a read-only tab with the integration code. The editor displays that snippet first and uses it for the Preview copy action.

## Run code and render output

Use the same component for explicit execution instead of a live preview. Supply `runSource` and `renderOutput` in place of `renderPreview`.

```tsx
<PreviewCodeEditor
  title="JSON parser"
  files={[{ name: "input.json", language: "json", value: '{"ready":true}' }]}
  runSource={(files) => JSON.parse(files[0]?.value ?? "") as unknown}
  renderOutput={({ state }) => {
    if (state.status === "success")
      return <pre>{JSON.stringify(state.output, null, 2)}</pre>;
    if (state.status === "error") return <p>{String(state.error)}</p>;
    return <p>Edit JSON and select Run.</p>;
  }}
/>
```

The editor and output appear together in resizable panels. Run with the button or Ctrl/Cmd + Enter. Set `direction="vertical"` for stacked panels. The executor receives a snapshot of editable files (not the optional usage tab) and an AbortSignal. Synchronous and asynchronous results are supported. Starting a new run, clearing output, resetting code or unmounting aborts the previous signal and ignores stale results. Actual cancellation requires cooperation from the executor.

The renderer receives idle, running, success (typed output), or error state, plus a clear callback. Use any React output component, including an external console. No console dependency is required. The host owns execution and sandboxing; this component does not evaluate code.

[Try explicit execution](/ui/components/preview-code-editor/explicit-execution).

## Toggle the output panel

Both preview modes accept `outputLabel` (for example, "Console") and `defaultOutputOpen`. The toolbar's Show/Hide action collapses the panel without clearing its contents or unmounting the renderer. In live mode, the output sits below the Preview/Code views and remains accessible while switching between them.

For a live preview, pass a zero-argument `renderOutput` alongside `renderPreview`. The host owns the output state and capture mechanism; PreviewCodeEditor never intercepts the global console.

```tsx
<PreviewCodeEditor
  title="Interactive component"
  files={files}
  renderPreview={renderPreview}
  renderOutput={() => <Console messages={messages} onClear={clear} />}
  outputLabel="Console"
  defaultOutputOpen={false}
/>
```

[Try a live React console](/ui/components/preview-code-editor/live-console).
