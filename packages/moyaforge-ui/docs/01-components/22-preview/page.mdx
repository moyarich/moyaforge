## Usage

```mdx
import PreviewExample from "./PreviewExample.tsx";

<PreviewExample />
```

```tsx
import {
  Preview,
  PreviewHeader,
  PreviewTitle,
  PreviewActions,
  PreviewCodeToggle,
  PreviewCopyButton,
  PreviewContent,
  PreviewSource,
} from "@/components/moyaforge/components/Preview";
import ButtonExample from "./ButtonExample";
import source from "./ButtonExample.tsx?raw";

<Preview source={source}>
  <PreviewHeader>
    <PreviewTitle>Button</PreviewTitle>
    <PreviewActions>
      <PreviewCodeToggle />
      <PreviewCopyButton />
    </PreviewActions>
  </PreviewHeader>
  <PreviewContent>
    <ButtonExample />
  </PreviewContent>
  <PreviewSource code={source} language="tsx" />
</Preview>;
```

Use `PreviewContent asChild` and `PreviewSource asChild` to compose one DOM-forwarding child, such as a custom layout or editor. `asChild` does not compile or run edited source.\n\nThe `?raw` import is supported by Vite. Preview itself does not depend on Vite or MDX; other consumers can pass source strings. You can omit, reorder, or replace slots. The basic `<Preview source={source}>…</Preview>` shorthand still works.

## Custom trigger with `asChild`

Use `asChild` on the code toggle to apply its behavior to a custom button without nesting interactive elements.

```tsx
<PreviewCodeToggle asChild>
  <button type="button" className="my-code-trigger">
    Show source
  </button>
</PreviewCodeToggle>
```

The child must be a single native button or a button-like React component that forwards click handlers and ARIA attributes. For non-button elements, provide your own appropriate accessible semantics and handlers instead of using this trigger.

## Theme variables

Use `--mf-preview-background`, `--mf-preview-border`, `--mf-preview-radius`, and `--mf-preview-padding` in application CSS.

## External examples such as CSS Color Parser

A consuming application can use the same structure as CSS Color Parser's `FunctionExample` and `CssColorEditor`: import a standalone example `.tsx` module into MDX and supply its raw source using `?raw`. Put the interactive parsing UI in `PreviewContent`; wrap an optional editor in `PreviewSource asChild`. Preview has no parser-specific dependency.
