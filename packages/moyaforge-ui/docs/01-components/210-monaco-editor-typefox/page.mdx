# Monaco Editor TypeFox

import { MonacoEditorTypeFox } from "@moyarich/moyaforge-monaco/components/MonacoEditorTypeFox";

A multi-file code editor with read-only mode and copy support.

## Installation

<CodeGroup label="Install Monaco Editor TypeFox">
<CodeTab label="MoyaForge CLI">

```sh
npx @moyarich/moyaforge-cli@latest add monaco-editor-typefox
```

</CodeTab>
<CodeTab label="shadcn">

```sh
npx shadcn@latest add moyarich/moyaforge/monaco-editor-typefox
```

</CodeTab>
</CodeGroup>

In an existing React app, ensure these runtime dependencies are installed:

```sh
npm install @moyarich/moyaforge-monaco @typefox/monaco-editor-react@~8.0.2 monaco-languageclient@~11.0.2 @codingame/monaco-vscode-editor-api@^37.6.1 lucide-react
npm install @codingame/monaco-vscode-standalone-languages@^37.6.1 @codingame/monaco-vscode-standalone-typescript-language-features@^37.6.1 @codingame/monaco-vscode-standalone-css-language-features@^37.6.1 @codingame/monaco-vscode-standalone-json-language-features@^37.6.1 @codingame/monaco-vscode-standalone-html-language-features@^37.6.1
```

For Vite, register `monacoReactTypesPlugin(import.meta.dirname)` from `@moyarich/moyaforge-monaco/vite` in `vite.config.ts` and call `configureTypeFoxWorkers()` from `@moyarich/moyaforge-monaco/typefox` once at application startup. If using React Monaco too, call `initializeSharedMonaco()` from `/shared` instead. Other bundlers need their own worker setup.

For editor worker architecture and shared initialization details, see [Monaco runtime](../../../../../docs/04-development/30-monaco-runtime/page.mdx).

The editor setup belongs in your application's `main.tsx`, **not** inside the component. For standalone TypeFox applications:

```ts
import { configureTypeFoxWorkers } from "@moyarich/moyaforge-monaco/typefox";

configureTypeFoxWorkers();
```

## Usage

::: code-preview TypeFox workspace

<LiveMonacoEditorTypeFox
  files={[{ name: "index.ts", value: "const answer = 42;" }]}
  height={320}
/>

:::

For source installs, the `@/` path maps to your configured UI directory. Package consumers can import from `@moyarich/moyaforge-monaco/components/MonacoEditorReact` or `/MonacoEditorTypeFox` instead.

```tsx
import { MonacoEditorTypeFox } from "@/components/ui/MonacoEditorTypeFox/MonacoEditorTypeFox";

<MonacoEditorTypeFox
  files={[
    { name: "index.ts", value: "const answer = 42;" },
    { name: "styles.css", value: "body { margin: 0; }" },
  ]}
  height={320}
/>;
```

Use `onSave` to handle Save or Ctrl/Cmd+S and persist changes. Use `onFileChange` to track edits.

To connect a language server, pass `languageClientConfig` with the same configuration accepted by TypeFox's `MonacoEditorReactComp` (typed as `LanguageClientConfig` from `monaco-languageclient/lcwrapper`):

```tsx
<MonacoEditorTypeFox files={files} languageClientConfig={languageClientConfig} />
```

The host must provide a running language server and its transport; MoyaForge does not start one. Initialize shared VS Code services once at application startup when mounting both Monaco integrations.

<details>
<summary>Advanced options</summary>

- `activeFile` and `onActiveFileChange` control the selected file.
- `theme` overrides the inherited light/dark appearance.
- `options`, `vscodeApiConfig`, `languageClientConfig`, `onReady`, and `onError` customize TypeFox.
- `showCopyButton` and `showFileTabs` control toolbar visibility.
- `className` and `--mf-monaco-*` CSS variables customize styling.

The installed `components/MonacoEditorTypeFox/README.md` includes additional dependency and setup guidance.

</details>

## Styling

Customize the editor using `className` and the public `--mf-monaco-*` CSS variables described in Advanced options.
