# Source discovery and README exclusion

A source defines **where to look**, **which files match**, and **which matching
files count as pages**. Use the small `docs` tree from the
[registry overview](../page.mdx) to choose one of the following policies.

All examples assume `registry.config.ts` is at your app root, alongside `docs/`.
The `docs` source key supplies the `/docs` URL prefix.

## Start with canonical page files

Use this complete configuration when each page lives in `page.md` or `page.mdx`:

```ts filename="registry.config.ts"
import type { RegistryConfiguration } from "@moyarich/moyaforge-mdx/vite";

export default {
  sources: {
    docs: {
      base: "./docs",
      include: ["**/page.{md,mdx}"],
      pageFiles: "canonical",
    },
  },
} satisfies RegistryConfiguration;
```

`canonical` is the default, so you may omit `pageFiles` here. Even with a broader
`include`, this policy only registers files named `page.md` and `page.mdx`.

| File in the source | Registered |
| --- | --- |
| `page.md` | Yes |
| `01-installation/page.md` | Yes |
| `02-authoring/page.md` | Yes |
| `notes.md` | No |
| `README.md` | No |

This is a good default for folders that also contain example source or supporting
Markdown. The `base` directory must exist, but it may be empty.

## Include ordinary Markdown deliberately

If `notes.md` should also be a page, change the source to:

```ts filename="registry.config.ts"
import type { RegistryConfiguration } from "@moyarich/moyaforge-mdx/vite";

export default {
  sources: {
    docs: {
      base: "./docs",
      include: ["**/*.{md,mdx}"],
      pageFiles: "all",
      exclude: ["**/{README,readme}.{md,mdx}"],
    },
  },
} satisfies RegistryConfiguration;
```

Now the three canonical pages and `notes.md` are registered. README files remain
available on disk without becoming documentation routes. If you remove the
exclusion, matching README files become pages too.

Discovery applies these rules together:

1. `base` establishes the source directory.
2. `include` finds candidate files relative to that directory.
3. `exclude` removes matching candidates.
4. `pageFiles` applies the canonical-only or all-Markdown policy.

`all` does not override `include`. For example, an include pattern of
`**/page.{md,mdx}` still selects only canonical page files, even with `pageFiles: "all"`.
Patterns support brace expansion, as used in the README exclusion above.

## Keep page selection separate from page visibility

An excluded file never reaches the page registry. By contrast, a discovered
page with `navigation: hidden` still has metadata and a route. A page with
`navigation: disabled` retains its page record but is absent from routes.
See the [live registry example](../20-metadata-navigation/page.mdx#compare-the-registry-views)
to compare those views.

Numeric prefixes control ordering when frontmatter does not specify `order`.
Public route segments come from page titles, so `01-installation/page.md` with
`title: Quick setup` becomes `/docs/quick-setup`, not `/docs/01-installation`.

## Add non-page source metadata

A source may also read JSON files through `metadata`:

```ts
const packageDocs = {
  base: "./packages",
  include: ["**/page.{md,mdx}"],
  exclude: ["**/node_modules/**", "**/dist/**"],
  metadata: ["*/package.json"],
};
```

Here `packageDocs` is a source-options fragment to add under `sources`.
The package JSON data is exposed as source metadata; it does not create extra
routes. For a monorepo, add exclusions for any templates or docs trees that
belong to a different registered source.

## Verify changes

In this repository, run `npm run check:links` after changing source rules or moving
pages. The discovery regression tests in
`packages/moyaforge-mdx/tests/content/content.test.js` also check the playground
and generated-template policies against canonical pages, notes, and README files.

Keep application-specific exclusions in its source configuration rather than
changing the shared definition of a canonical page.
