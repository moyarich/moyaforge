# Metadata, navigation and links

`discoverContent()` reads YAML frontmatter, extracts heading IDs, and builds normalized page records **without running the MDX page components**. It returns `registry`, `inputs`, `headings`, and optional `metadata` such as package JSON.

## Virtual modules

The Vite registry adapter exposes three distinct module surfaces:

| Module | Use |
| --- | --- |
| `virtual:moyaforge-mdx/metadata` | Plain page, route, navigation, heading and source metadata; **no React page imports** |
| `virtual:moyaforge-mdx/lazy-registry` | Source-grouped dynamic page loaders, avoiding eager MDX module imports |
| `virtual:moyaforge-mdx/registry` | Compatibility module with eager `pages` and lazy `lazyPages` maps |

~~~ts
import { pages, routes, navigation, tree } from "virtual:moyaforge-mdx/metadata";
import { sources } from "virtual:moyaforge-mdx/lazy-registry";

const loadPage = sources.docs.lazyPages["04-development/page.mdx"];
const component = await loadPage();
~~~

Use the types-only `@moyarich/moyaforge-mdx/virtual` entry in your TypeScript `compilerOptions.types` or `vite-env.d.ts`. The `@moyarich/moyaforge-mdx/vite` entry is for the actual Vite plugins. MDX frontmatter is stored in registry metadata; `createMdxOptions({ exportFrontmatter: true })` is only for legacy consumers needing a compiled JS export.

## Visibility, navigation, and sidebar

- `navigation: visible` (default) produces a route and a navigation entry; `hidden` remains routable without a sidebar entry; `disabled` is omitted from routes and navigation.
- `buildNavigationTree` and `flattenNavigation` derive nested navigation using ordered filenames. A missing directory landing page can be a **virtual group**, not an invented URL.
- Frontmatter `sidebar.group: true` allows a source-root `page.mdx` to become a clickable group heading. Its separate disclosure toggle expands children. Use `sidebar.collapsible`, `sidebar.defaultOpen`, or `sidebar.label` to tune behavior.
- The `icon` field accepts a Lucide kebab-case name, stored as metadata; UI rendering remains optional.

~~~yaml
---
title: UI Components
label: Overview
icon: folder-open
sidebar:
  group: true
  collapsible: true
  defaultOpen: true
---
~~~

## TOC, heading IDs, and links

`extractPageHeadings` recognizes Markdown and MDX syntax, including static JSX surrounding headings, using the shared remark/rehype slug pipeline. Duplicates retain their canonical generated IDs. Headings rendered **later by React components** cannot be discovered at build time.

`resolveTocOptions`, `filterTableOfContents`, and `getTableOfContents` apply project defaults and page-specific `toc` overrides. `toc: false` disables the outline, and an outline with no matching headings is omitted.

`validateInternalLinks` checks page links against registered public routes and heading anchors. `checkContentLinks` and `formatLinkIssues` support CI diagnostics for missing pages, missing anchors, and invalid references. The checker handles Markdown links and literal MDX anchor `href` values; dynamic JSX expressions cannot be statically validated. Run `npm run check:links` after moving documentation.

See [Routing and navigation](../../../01-routing/page.mdx) for host React Router integration, and [Development](../../page.mdx) for source-file links versus public routes.
