# Registry metadata and navigation

Once discovery has selected your files, MoyaForge builds several views of the
same page records. Each view answers a different question. The application uses
metadata for navigation and a separate loader when it needs to render an article.

## Compare the registry views

Start with the three canonical pages from the
[source-discovery guide](../10-source-files/page.mdx). Their frontmatter titles
are Guide, Installation, and Authoring; their source key is `docs`.

| View | Contains | Use it for |
| --- | --- | --- |
| `pages` | All discovered pages, including hidden and disabled pages | Inspecting the complete inventory and its metadata. |
| `routes` | Visible and hidden pages; no disabled pages | Route matching and deciding whether a page can be opened. |
| `navigation` | Visible pages in sidebar display order | Previous/next links or a flat navigation list. |
| `tree` | Visible navigation with parent/child relationships | Nested navigation, including virtual folders without landing pages. |

**Try it:** hide Installation. It stays in `pages` and `routes`, but leaves
`navigation`. Disable it next: its page record remains, but its route is removed.
Changing the source key demonstrates how the route prefix is generated.

## Read metadata without loading articles

Use the metadata module for application chrome:

```ts filename="src/page-inventory.ts"
import {
  pages,
  routes,
  navigation,
  tree,
  headings,
  sourceMetadata,
} from "virtual:moyaforge-mdx/metadata";

export const inventory = { pages, routes, navigation, tree };
```

`RegistryPage` records include `source`, `file`, `title`, `path`, `parentPath`,
`order`, `navigation`, and the resolved page options. Frontmatter supplies
metadata such as description, icon, sidebar settings, and outline settings.

These imports do not import the React page components. `headings` contains the
compiler-derived heading trees, keyed by `source/file`. `sourceMetadata` contains
optional JSON files selected with the source’s `metadata` patterns.

## Load an article by its source filename

The lazy registry holds page loaders, grouped by source. A loader key is the
source-relative filename, not the public URL:

```text
Source key:       docs
Source filename:  01-installation/page.md
Public route:     /docs/installation
```

Use a route record to select the correct loader:

```ts filename="src/load-article.ts"
import { routes } from "virtual:moyaforge-mdx/metadata";
import { sources } from "virtual:moyaforge-mdx/lazy-registry";

export async function loadArticle(path: string) {
  const page = routes.find((candidate) => candidate.path === path);
  if (!page) return undefined;

  const load = sources[page.source]?.lazyPages[page.file];
  if (!load) throw new Error(`Missing page loader: ${page.source}/${page.file}`);

  const { default: Article } = await load();
  return Article;
}
```

Calling `loadArticle("/docs/installation")` returns a React component for the
article when that route exists. Your router decides when to load and render it.
For the framework’s ready-made route adapter, follow
[Routing and navigation](../../../01-routing/page.mdx).

The third module, `virtual:moyaforge-mdx/registry`, exposes eager `pages` maps
alongside lazy maps. Import it when you intentionally need eager components;
metadata plus lazy loaders keeps navigation separate from article loading.

## Render sidebar groups

A navigation tree describes hierarchy; source configuration supplies group
presentation. Combine them using `buildDocumentationGroups`:

```ts filename="src/navigation.ts"
import { buildDocumentationGroups } from "@moyarich/moyaforge-mdx/navigation";
import { routes } from "virtual:moyaforge-mdx/metadata";
import registry from "../registry.config";

export const groups = buildDocumentationGroups(routes, registry.sources);
```

Pass `groups` to Sidebar V1 or its `Navigation` component. A visible source-root
page with `sidebar.group: true` becomes the linked heading, with child pages
below it. Otherwise the source’s configured `navigation.label` supplies the
group label. The live example uses a promoted Guide landing page.

Missing ancestor landing pages can still produce virtual directory nodes. Those
nodes organize children without inventing a routable article for the directory.
For the author-facing options, see
[frontmatter configuration](../../../02-mdx/10-markdown-and-mdx/page.mdx#frontmatter).

## Render an article’s outline

Look up headings with the source key and original filename, then apply the page’s
`toc` setting:

```ts filename="src/page-outline.ts"
import { getTableOfContents } from "@moyarich/moyaforge-mdx/toc";
import { routes, headings } from "virtual:moyaforge-mdx/metadata";

export function getPageOutline(path: string) {
  const page = routes.find((candidate) => candidate.path === path);
  if (!page) return undefined;

  return getTableOfContents(
    headings[`${page.source}/${page.file}`] ?? [],
    page.toc,
  );
}
```

The result provides filtered headings and resolved display options. An outline
is omitted when disabled or when no headings match its depth range.

Heading extraction uses the same slug pipeline as page compilation, including
duplicate-heading IDs. It can read authored Markdown and static MDX headings;
it cannot discover headings created later inside a rendered React component.

## Configure TypeScript and check links

In your app’s existing TypeScript configuration, include the virtual module types:

```json
{
  "compilerOptions": {
    "types": ["vite/client", "@moyarich/moyaforge-mdx/virtual"]
  }
}
```

Merge that fragment with existing settings. The types-only `/virtual` entry
provides declarations; `/vite` exports the actual Vite plugins. Registry metadata
already contains frontmatter, so compiled JavaScript frontmatter exports are only
needed when another consumer explicitly imports them.

In this repository, run the documentation link checker after moving pages or
changing route titles:

```sh
npm run check:links
```

It checks Markdown links and literal MDX `href` values against registered routes
and heading anchors. Diagnostics distinguish missing pages, missing anchors, and
invalid references. Dynamic JSX link expressions cannot be checked statically.
