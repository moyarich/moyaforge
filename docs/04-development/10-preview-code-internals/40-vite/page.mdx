# Vite and file-backed previews

The host first discovers documentation pages and builds a shared registry. Pass the **same context** to the MDX mapping and Vite plugin:

```ts
import {
  createPreviewCodeRegistry,
  createPreviewCodePlugin,
  resolvePreviewCodeSource,
} from "@moyarich/moyaforge-mdx/vite";

const codePreview = createPreviewCodeRegistry({
  root: contentRoot,
  sources: registry.sources,
  pages: discovered.pages,
});

export default defineConfig({
  plugins: [
    createPreviewCodePlugin({
      codePreview,
      componentRoots: [
        ...codePreview.componentRoots,
        "../../packages/moyaforge-ui/src/components",
      ],
    }),
    // ...your MDX and React plugins
  ],
});
```

`createPreviewCodeRegistry` registers eligible sibling files and exposes `componentRoots`, `modules`, `keysByPath`, and `basesByPath`. `createPreviewCodePlugin` may extend those maps with explicitly allowed React component roots. `resolvePreviewCodeSource` validates relative references against the registered file inventory and optional `#NamedExport` suffix.

The plugin exposes lazy component and raw-source loader maps:

- `virtual:moyaforge-mdx/preview-code-components` for registered React components;
- `virtual:moyaforge-mdx/preview-code-sources` for raw file text (`?raw`);
- `virtual:moyaforge-mdx/react-preview/...` for inline compiled modules, including trusted CSS.

Named TSX and JSX modules are compiled by Vite/Oxc; selected MDX modules use `@mdx-js/mdx` **at build time**, not with browser `eval`. Relative imports resolve from the authored page's location. Vite watches registered component roots for changes; missing or unregistered components fail with a diagnostic.

See the working [playground Vite configuration](../../../../apps/playground/vite.config.ts) and [component registry tests](../../../../packages/moyaforge-mdx/tests/vite/preview-code-component-roots.test.js). The CLI playground template also wires the same features.
