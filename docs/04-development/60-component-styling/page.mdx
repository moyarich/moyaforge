# Component styling conventions

MoyaForge uses **CSS classes for presentation**. Do not add attribute selectors such as `[data-moyaforge-...]`, `[data-expanded]` or `[data-level]` to component stylesheets. An attribute may remain in JSX if JavaScript, accessibility, or existing integration tests read it; it must not be required for styling.

## Class names

- **Component root or slot:** a descriptive `.mf-*` class, such as `.mf-demo`, `.mf-doc-outline`, `.mf-sidebar-v2` or `.mf-monaco-copy-button`.
- **Component states:** conditional classes such as `.is-expanded`, `.is-inline` or `.is-menu-open`; ensure the component's JSX updates them whenever the state changes.
- **Variants and layout:** explicit classes such as `.mf-level-3`, `.mf-no-sidebar` or `.mf-no-outline` instead of data-attribute value selectors.
- **User overrides:** merge user-provided `className` with required component classes rather than replacing either one. For polymorphic components, apply the merged class after spreading remaining props.

The `CodeGroup`, `Preview`, and `Monaco` components already expose test/behavior hooks. Keep these DOM attributes where downstream tests or scripts use them, but write styling rules against classes.

## CSS custom properties

| Purpose                                         | Prefix               | Example                                              |
| ----------------------------------------------- | -------------------- | ---------------------------------------------------- |
| Public component override or shared theme token | `--mf-*`             | `--mf-doc-outline-top`, `--mf-copy-button-padding`   |
| Derived, component-private value                | `--_mf-*`            | `--_mf-doc-outline-top`, `--_mf-copy-button-padding` |
| Third-party external tokens                     | Keep vendor contract | Shiki's `--shiki-dark`                               |

Derive a private variable from the public input at the component root and use the private value in declarations:

```css
:root {
  --_mf-demo-background: var(--mf-demo-background, transparent);
  --_mf-demo-padding: var(--mf-demo-padding, 0);
}
.mf-demo {
  padding: var(--_mf-demo-padding);
  background: var(--_mf-demo-background);
}
```

Applications should override **only public** `--mf-*` properties. Private properties are implementation details and may change. The old unprefixed names such as `--demo-padding`, `--docs-sidebar-width` and `--wide-panel-width` have been renamed to `--mf-demo-padding`, `--mf-docs-sidebar-width` and `--mf-wide-panel-width`. Update consuming styles when migrating.

## Safeguards

The architecture test `tests/architecture/component-style-conventions.test.js` scans **all repository CSS files** and rejects data-attribute selectors and nonconforming custom property names.
It exempts only third-party namespace inputs such as Shiki. UI render tests in `packages/moyaforge-ui/tests/unit/component-style-hooks.test.tsx` verify class names and conditional states.
