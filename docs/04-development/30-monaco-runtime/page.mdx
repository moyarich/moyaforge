# Monaco editor runtimes

`@moyarich/moyaforge-monaco` owns optional Monaco components and worker integrations. It is independent of the MDX compiler and should not be imported merely to render ordinary documentation UI.

## Choose one worker strategy

| Editor combination | Run once in the application's entry point                                 |
| ------------------ | ------------------------------------------------------------------------- |
| React Monaco only  | `configureReactWorkers()` from `@moyarich/moyaforge-monaco/workers/configureReactWorkers`         |
| TypeFox only       | `configureTypeFoxWorkers()` from `@moyarich/moyaforge-monaco/workers/configureTypeFoxWorkers`     |
| Both editors       | `await initializeMonacoVscodeRuntime()` from `@moyarich/moyaforge-monaco/runtime/initializeMonacoVscodeRuntime` |

For both editor engines:

```tsx
import { createRoot } from "react-dom/client";
import { initializeMonacoVscodeRuntime } from "@moyarich/moyaforge-monaco/runtime/initializeMonacoVscodeRuntime";
import { App } from "./App.js";

await initializeMonacoVscodeRuntime();
createRoot(document.getElementById("root")!).render(<App />);
```

The shared initializer configures TypeFox workers, points `@monaco-editor/react` at the same VS Code-compatible editor API, and initializes shared services once. It caches initialization. **Do not also call either standalone worker initializer.**

Standalone React Monaco supplies `MonacoEnvironment.getWorker`. TypeFox uses `getWorkerUrl` and `getWorkerOptions`. Monaco prioritizes `getWorker` when both exist; mixing standalone strategies can cause a configuration error. Shared runtime setup shares the worker protocol/services, not individual Worker objects.

## Custom workers

React Monaco accepts the native `monaco.Environment` configuration. A host-provided `getWorker` or `getWorkerUrl` takes precedence over the built-in factory. Pass `typescript.compilerOptions` in the same object to override TypeScript defaults.

```ts
import {
  configureReactWorkers,
  getDefaultReactWorker,
} from "@moyarich/moyaforge-monaco/workers/configureReactWorkers";
import CustomWorker from "./custom.worker?worker";

configureReactWorkers({
  getWorker(moduleId, label) {
    if (label === "custom") return new CustomWorker();
    return getDefaultReactWorker(moduleId, label);
  },
});
```

TypeFox and the shared runtime accept the native `WorkerFactoryConfig` from `monaco-languageclient/workerFactory`. Additional `workerLoaders` extend the defaults, and matching labels override them. Pass `typescript.compilerOptions` to override TypeScript defaults, for example `{ typescript: { compilerOptions: { strict: true } } }`. Custom `paths` entries merge with the built-in React type paths.

```ts
import { Worker } from "monaco-languageclient/workerFactory";
import { configureTypeFoxWorkers } from "@moyarich/moyaforge-monaco/workers/configureTypeFoxWorkers";
import CustomWorkerUrl from "./custom.worker.ts?worker&url";

configureTypeFoxWorkers({
  workerLoaders: {
    custom: () => new Worker(
      new URL(CustomWorkerUrl, import.meta.url),
      { type: "module" },
    ),
  },
});
```

For an application using both editors, pass the same TypeFox configuration to `initializeMonacoVscodeRuntime(config)` instead. Configure the runtime before mounting editors; the first initialization owns worker configuration. Custom workers must implement the protocol expected by the requesting service. Register any additional language contributions or providers through Monaco or TypeFox's native APIs.

### Host-managed worker registration

Use `createMonacoVscodeWorkerConfig()` when your host owns worker registration. The helper returns lazy worker loaders and merges any overrides by label. Call `useWorkerFactory()` when the host is ready to register them.

```ts
import { useWorkerFactory } from "monaco-languageclient/workerFactory";
import { createMonacoVscodeWorkerConfig } from "@moyarich/moyaforge-monaco/workers/createMonacoVscodeWorkerConfig";

const workerConfig = createMonacoVscodeWorkerConfig();
useWorkerFactory(workerConfig);
```

This registers workers only. TypeScript defaults, React declaration libraries, and VS Code service startup are separate parts of runtime setup.

## Vite and TypeScript types

Register `monacoReactTypesPlugin(projectRoot)` from `@moyarich/moyaforge-monaco/vite/monacoReactTypesPlugin` in `vite.config.ts`. Add `@moyarich/moyaforge-monaco/vite/react-types` to the TypeScript `compilerOptions.types` list. The plugin provides `virtual:moyaforge-monaco/react-types` to supply the React, React DOM and CSS types expected by Monaco's TSX worker.

TypeFox optionally accepts `languageClientConfig`, but **the host must supply its own language server and transport**. MoyaForge does not start a language server.
