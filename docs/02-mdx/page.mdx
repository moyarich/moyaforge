# Markdown and MDX

The MDX package discovers content and provides compiler conventions independently of the React documentation shell.

## Register your content

Define sources relative to your app. A source can contain Markdown pages, MDX pages, and metadata.

```js
// registry.config.js
export default {
  sources: {
    docs: {
      base: "../../docs",
      include: ["**/*.md", "**/page.mdx"],
      navigation: { label: "Guide", order: 1 },
    },
  },
};
```

## Configure Vite

The registry plugin generates metadata and lazy imports. The MDX plugin compiles your content into React components.

```js
import mdx from "@mdx-js/rollup";
import react from "@vitejs/plugin-react";
import { createMdxOptions } from "@moyarich/moyaforge-mdx";
import { mdxRegistryPlugin } from "@moyarich/moyaforge-mdx/vite";
import registry from "./registry.config.js";

export default {
  plugins: [
    mdxRegistryPlugin({ registry, root: import.meta.dirname }),
    { enforce: "pre", ...mdx(createMdxOptions()) },
    react({ include: /\.(?:js|jsx|md|mdx|ts|tsx)$/ }),
  ],
};
```

## Control page visibility

Frontmatter supports `title`, `description`, `order`, `navigation`, and `toc`. Set `navigation: hidden` to keep a page linkable without displaying it in the sidebar. Set `navigation: disabled` to exclude it from the routable inventory.

## Use components in MDX

Import a component directly into a page, then render it alongside your Markdown. See the [examples](/ui) for working integrations.

For the implementation of preview directives, code tabs and source-only scripts, see [Code preview internals](../04-development/10-code-preview-internals/page.mdx).

The complete content-discovery and virtual-module contracts are described in [Content registry internals](../04-development/20-content-registry/page.mdx). Broad `pageFiles: "all"` globs need explicit README exclusions; the playground and CLI templates include them.

The compiler includes GFM, frontmatter parsing, heading slugs, and table-of-contents extraction. A compiled JavaScript frontmatter export is opt-in. See [MDX conventions](../mdx-conventions.md) for details.

## Page titles and URLs

Use `title` as the single page name in frontmatter:

```yaml
---
title: Getting started
---
```

MoyaForge generates `id: "getting-started"` from that title. The page appears under the same title in navigation and uses `/docs/getting-started` as its URL when it is a child of the `docs` source. Parent pages contribute their own title-based URL segments. Source landing pages keep their source URL, such as `/docs`.

IDs are lowercase, with punctuation and whitespace replaced by hyphens. Accents are normalized, and non-Latin letters are retained. Numeric folder prefixes continue to control order. Sibling pages must have distinct generated URLs. Changing a title changes its URL, so update incoming links; source-file links are resolved against the current registry.

The old page `label` frontmatter field is removed. Source-group and table-of-contents labels still name their own UI sections and do not override page titles.
