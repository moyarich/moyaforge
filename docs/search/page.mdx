# SQLite search

MoyaForge offers optional SQLite-backed search for documentation. The search adapter is independent of the React UI component.

## Generate a site with search

```sh
npx @moyarich/moyaforge-cli@latest create --search
npm run dev
```

The CLI enables the SQLite Vite plugin, adds `@moyarich/moyaforge-search-sqlite`, and installs the existing `Search` UI component from `packages/moyaforge-ui/src/components/Search/` using the component registry.

The generated `src/SearchPanel.tsx` contains **application-specific integration**, not another search input implementation. It imports the installed `Search` component, calls `searchPages()`, and links matching results to MDX routes.

Without `--search`, the starter uses a no-op `SearchPanel` and does not install the optional search component or SQLite adapter.

## Use the search UI in your own app

Install the reusable input independently with:

```sh
npx @moyarich/moyaforge-cli@latest add search
```

It provides an input with configurable `onChange`, `value`, `icon`, and `inputProps`. It **does not** index documents or choose a router for you.

For a site using the SQLite client and the generated MDX metadata:

```tsx
import { useState } from "react";
import { Link } from "react-router-dom";
import { Search } from "./components/ui/Search/Search.js";
import { searchPages } from "@moyarich/moyaforge-search-sqlite/client";
import { routes } from "virtual:moyaforge-mdx/metadata";

export function SearchPanel() {
  const [results, setResults] = useState<string[]>([]);

  return (
    <div>
      <Search
        inputProps={{ "aria-label": "Search documentation" }}
        onChange={async (event) =>
          setResults(await searchPages(event.currentTarget.value))
        }
      />
      {results.map((result, index) => {
        const page = routes.find(
          (page) => page.title === result || page.path === result,
        );
        return (
          <Link key={index} to={page?.path ?? "/docs"}>
            {result}
          </Link>
        );
      })}
    </div>
  );
}
```

## Configure the Vite adapter manually

When configuring an application yourself, use the same authored-content registry as your MDX plugin:

```ts
import { sqliteSearchPlugin } from "@moyarich/moyaforge-search-sqlite/vite";

// Add alongside your MDX and React Vite plugins:
sqliteSearchPlugin({ registry, root: import.meta.dirname });
```

The adapter prepares the index for development and emits the database as a production asset. The browser client queries it on demand.

## Use the standalone API

You can build and query a search index without React, MDX, or Vite:

```js
import initSqlJs from "sql.js";
import { buildSearchDatabase, querySearchDatabase } from "@moyarich/moyaforge-search-sqlite";

const SQL = await initSqlJs();
const bytes = buildSearchDatabase(SQL, [
  { key: "docs/page.mdx", title: "Welcome", description: "", body: "Welcome to the documentation" },
]);
const database = new SQL.Database(bytes);
const results = querySearchDatabase(database, "documentation");
```

Search results are document identifiers; your application maps them to the appropriate links using its routing and content metadata.
