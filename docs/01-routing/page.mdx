# Routing and navigation

Use the registry to load documentation pages inside your React Router. Choose `HashRouter` for static hosting or `BrowserRouter` when your server serves the app for each page URL.

## Render documentation pages

`RegistryRoutes` reads the routes and lazy page loaders generated by the MDX Vite plugin. Register `DocumentationLink` as the MDX anchor renderer so links to known documentation pages use the router.

```tsx filename="src/App.tsx"
import { MDXProvider } from "@mdx-js/react";
import { HashRouter } from "react-router-dom";
import { DocumentationLink } from "@moyarich/moyaforge/headless";
import { RegistryRoutes } from "@moyarich/moyaforge/registry-routes";

export function App() {
  return (
    <HashRouter>
      <MDXProvider components={{ a: DocumentationLink }}>
        <RegistryRoutes />
      </MDXProvider>
    </HashRouter>
  );
}
```

For an existing app, place `RegistryRoutes` inside its router and pass `renderPage` to wrap each article in your documentation shell. It scrolls to and focuses heading links after the destination page loads.

## Links authored in MDX

Documentation authors can write either public route links or, when the host enables the source-link transform, actual relative source-file links:

```mdx
[Code Block](/ui/components/code-block)
[Code Block source](../../packages/moyaforge-ui/docs/01-components/10-code-block/page.mdx)
```

The first link is an existing registry route. The second is resolved against the authoring MDX file's directory at compilation and mapped to the matching public route. Do not copy the second relative path to unrelated pages: relative source-file paths depend on the current file's location.

The host router handles URLs after compilation: the same public `/ui/components/code-block` route appears under `#/ui/components/code-block` when using a `HashRouter`. These transforms are optional and should not be confused with repository-relative `sourcePath` metadata, which is for GitHub edit links.

See [Development](/docs/development) for configuration, GitHub source-viewer behavior, limitations, and verification.

## Navigate and resolve results

Use React Router's `Link` or `NavLink` for links. For search results, use `createContentRouting(routes).searchResultPages(keys)` to resolve indexed document keys to pages. See the [SQLite search guide](/docs/search) for the full setup.

Disabled pages are excluded from routing. Hidden pages remain routable but stay out of the sidebar. Use the `notFound` prop to choose what appears at an unknown URL.
